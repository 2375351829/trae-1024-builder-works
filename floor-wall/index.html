关于数据源与跨域限制 About the Data

这个作品的每一个数字都来自真实接口，没有任何编造；同时它把「为什么网页读不到论坛数据」这件事讲清楚了。

① 数据从哪来
公开只读接口 forum.trae.cn/t/topic/325833.json，以及分页变体 /t/325833.json?page=N（每页 20 层）。字段：highest_post_number / last_posted_at / posts_count / participant_count / post_stream.posts[].cooked。
② 页面怎么自己拿到数据（自主探查）
浏览器同源策略要求跨域响应带 Access-Control-Allow-Origin 头。实测论坛接口不返回这个头（带 Origin 请求头复查过），网页里的 fetch() 必然被拦，抛 TypeError: Failed to fetch。
所以本页不靠人工复制粘贴，而是自己找路 —— 依次探查多条通道，命中即止：
· 本站镜像：GitHub Actions 定时把主帖全量楼层抓下来写成静态文件，Pages 对静态资源返回 access-control-allow-origin: *，页面可跨源直取；
· 论坛直连：官方若哪天开启 CORS 即刻生效；
· 公共 CORS 代理 ×2 与 RSS 通道：与前两条完全独立的第三方路径。
每次探查的逐条结果都摊在「探查日志」里，读者可以自己核对 —— 探查了几条、哪条命中、耗时多少、失败原因是什么。
③ 有效回复怎么判（两套口径都算给你看）
官方规则排除的是内容（「重复回复、灌水或与活动无关的内容」），不是排版格式。所以主判定取宽松：#我是 1024Builder# 这类带空白的写法，四行齐全，不算灌水。360 层回复中判出 213 层有效；若改用严格字面口径（正文必须含连续字面「我是1024Builder」），则只有 201 层。
④ 里程碑怎么算
官方规则原文：「盖到 128 楼，256 楼，512 楼，1024 楼…如所在楼层是无效回复，则顺延一楼」。本页从里程碑层起逐层向后找第一个有效模板回复，即该奖位的实际归属层。同一句「顺延一楼」，因判定口径不同会落到不同楼层 —— 里程碑卡上两套口径的结果都列出来了。

事实基线与数据说明 Ground Truth

页面内置一份采样快照（离线也能渲染时间轴）；页面会自己探查最新楼层 —— 依次尝试「本站镜像 / 论坛直连 / 公共代理 / RSS」四类通道，命中即止，全程不需要人工复制粘贴任何 JSON。「本站镜像」由 GitHub Actions 定时抓取主帖全量楼层写成静态文件，Pages 对静态资源返回 access-control-allow-origin: *，所以页面可跨源直取（实测同源 0.30s / 跨源 0.12s 命中）。

同一个「顺延一楼」，两种口径落在不同楼层：官方原文是「每个社区账号仅计 1 次有效参与；重复回复、灌水或与活动无关的内容不计入有效楼层」——排除的是内容，不是排版格式。所以本作品主判定取宽松（带空格但四行齐全的回帖不是灌水）：128 楼的奖顺延到 129 楼「硬气一点」。 若改用严格字面口径（正文必须含连续字面「我是1024Builder」），则 129 楼会被判无效，奖位会继续顺延到 133 楼「琦哈哈」。
另一个容易踩的坑：Discourse 把话题标签渲染成 <span class="hashtag-raw">#我是</span> 1024Builder#，「我是」和「1024Builder」之间隔着一个 HTML 标签而非空白字符 —— 直接在原始 HTML 里做字符串匹配会漏判这 12 层，所以必须先把 cooked 解码成纯文本再匹配。

手动导入 JSON（备用通道） Manual

正常情况下你用不到这里 —— 页面会自己探查（镜像 / 直连 / 代理 / RSS 四类通道），全程不需要你复制粘贴任何东西。这个面板是给「所有自动通道都没命中」时准备的兜底：把论坛 JSON 亲手贴进来，所有视图（时间轴 / 里程碑 / 我的楼层 / 预测器）会立刻用上最新楼层。

点「打开 JSON 链接」→ 浏览器会直接显示主帖的 JSON 文本（forum.trae.cn/t/topic/325833.json）。
在那个页面按 Ctrl+A 全选 → Ctrl+C 复制。
粘贴到下面文本框 → 点「解析并载入」。可一次粘贴多个 JSON（主帖 + 若干分页），解析器会逐个拆开并合并楼层。
