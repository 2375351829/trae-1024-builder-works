## 三、数据源与 CORS 限制（重点说明）

> 这一节同时也是作品本身的技术论点：**为什么一个网页能显示论坛数据，却不能自己去拉？**

### 3.1 实测结论：**跨域被浏览器拦截，无法直连**

| 检查项 | 实测结果 |
|---|---|
| `GET /t/topic/325833.json` 状态码 | `200` ✅ 接口本身完全公开可读 |
| 响应头 `Access-Control-Allow-Origin` | **不存在**（带 `Origin: https://example.com` 请求头复查，依然为空） |
| 响应头 `Vary` | `Accept-Encoding`（**不含 `Origin`** → 说明该站未开启 CORS） |
| 真实浏览器里 `fetch()` 的结果 | `TypeError: Failed to fetch`（Chrome 控制台：`Access to fetch at 'https://forum.trae.cn/...' from origin 'file://' has been blocked by CORS policy: No 'Access-Control-Allow-Origin' header is present`） |

**结论**：`forum.trae.cn` 没有开启 Discourse 的 `cors_enabled` 站点设置，因此任何第三方网页里的 `fetch()` 都会被浏览器同源策略拦下 ——
**这不是作品坏了，是浏览器的安全策略。** 于是本作品把「取数」设计成一条**主路径**：**打开 JSON 链接 → 复制全文 → 粘贴进输入框 → 解析**，3 步、10 秒。

> 附带说明：若未来论坛开启 CORS，或把本作品部署到 `forum.trae.cn` 同源下，页面里的实时抓取代码**无需改动即可自动生效**
> （`refresh()` / `loadSampledPages()` 两条路径均已实现并可被 `window.__FW.setTopicUrl(url)` 触发）。

### 3.2 页面为什么默认不弹红色报错

跨域受限是**已知的平台特性**，不是故障。因此页面默认展示的是一条**中性信息条**（浅色底 + 墨黑字 + 荧光绿描边）：

> **数据源**：内置真实快照（2026-10-21 00:44 采样，364 楼 / 361 个真实楼层）· 浏览器同源策略限制，页面无法自动拉取最新楼层 —— 点「**同步最新楼层**」一键更新（3 步）。

只有当**用户主动点击**「立即刷新 / 重试抓取 / 试试让页面直接抓取」而请求真的失败时，页面才会切到
**「⚠️ 实时数据获取失败」**告警条（含错误详情与重试按钮）。这是刻意的设计：**预期内的限制用说明条，真实的故障用告警条。**

### 3.3 降级策略（硬要求项，逐条落地）

| 要求 | 实现 |
|---|---|
| 顶部醒目提示 + 重试按钮 | `showBanner('err', …)` 渲染「⚠️ 实时数据获取失败」+「⟳ 重试抓取」按钮（黑底荧光绿投影） |
| 保留最近一次成功快照 | `localStorage['floorwall.snapshot.v1']`，写入时机 = 每次成功解析/抓取后；页面启动时若存在且比内置快照新，则自动恢复 |
| **绝不能白屏** | 抓取失败只走降级分支，DOM 主体照常渲染；`boot()` 外层还有 `try/catch` 兜底，初始化异常也会降级为最小可用页面 |
| 60 s 自动刷新 | `setInterval(60_000)`；页面不可见（`document.hidden`）时暂停；**检测到跨域失败后熔断暂停**，避免每分钟重复触发浏览器的 CORS 告警（手动重试即恢复） |

## 四、有效回复的判定（两套口径都算、都展示）

### 4.1 为什么要先解码 HTML

Discourse 会把话题标签渲染成：

```html
<p><span class="hashtag-raw">#我是</span> 1024Builder#</p>
```

「我是」与「1024Builder」之间隔着一个 **HTML 标签**，而不是空白字符。
所以直接在原始 `cooked` 里用字符串匹配会**漏判 12 层**。正确做法是**先把 `cooked` 解码成纯文本再匹配**。

### 4.2 判定规则

| 口径 | 规则 | 命中层数 |
|---|---|---|
| **宽松（主判定）** | 解码纯文本后匹配 `/我\s*是\s*1024\s*Builder/i` | **213 层** / 360 层回复 |
| 严格字面（对照） | 解码纯文本后含连续字面 `我是1024Builder` | **201 层**（把主帖公告一并计入则为 202） |
| 两者之差 | 含空白变体写法 | **12 层** |

**含空白变体的 12 个楼号**：66 / 94 / 113 / 114 / **129** / 134 / 160 / 244 / 294 / 313 / 336 / 358

**为什么主判定取宽松**：官方原文是「每个社区账号仅计 1 次有效参与；**重复回复、灌水或与活动无关的内容**不计入有效楼层」——
排除的是**内容**，**不是排版格式**。`#我是 1024Builder#`（中间带空格）且四行填写齐全，它不是灌水、也不是与活动无关，
它就是一次完整的有效参与。

### 4.3 同一个「顺延一楼」，两种口径落在不同楼层（本作品最有技术含量的地方）

官方规则原文：「盖到 128 楼，256 楼，512 楼，1024 楼等四个指定特殊楼层的朋友…**如所在楼层是无效回复，则顺延一楼**」

| 里程碑 | 宽松口径（主判定） | 严格字面口径（对照） |
|---|---|---|
| **128** | `128✗ → 129✓` → **129 楼「硬气一点」** | `128✗ → 129✗ → 130✗ → 131✗ → 132✗ → 133✓` → 133 楼「琦哈哈」 |
| **256** | `256✓` → 256 楼「鱼香肉丝没鱼老婆饼里没老婆夫妻肺片没老婆夫妻」 | `256✓`（一致） |
| 512 | 未达成 | 未达成 |
| 1024 | 未达成 | 未达成 |

页面上的**里程碑轨**会把两条链一起展示：主判定那条高亮，另一条以「口径对照」小字列出 —— **把规则的歧义算给读者看**。
